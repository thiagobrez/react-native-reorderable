# Require automated behavioral proof before publishing

V1 treats automated, user-observable tests as the publication gate: an exhaustively tested JavaScript semantic core, React Native Testing Library integration coverage, shared device scenarios across native iOS 27 and fallback iOS 27, iOS 26, and Android, Reassure checks on critical render paths, and clean-fixture validation of the exact package artifact. `agent-device` is the preferred device harness: version 0.20.10 is pinned because it includes the published selector-targeted drag gesture, including continuous source hold, timed movement, and destination hold ([callstack/agent-device#1567](https://github.com/callstack/agent-device/pull/1567)), together with the current iOS runner recovery and exact-target resolution fixes. Pointer planning is capability-based and preserves the shared semantic destination: Detox targets the named row's upper quarter for insertion before it, while Agent Device's center-only selector drag targets the predecessor on native SwiftUI. Detox remains the fallback for contracts that `agent-device` cannot express, including custom accessibility-action dispatch and lifecycle mutation during an in-flight gesture. Routine manual QA, implementation-detail assertions, silent retries, and uncovered contractual behavior are rejected because neither engine parity nor release confidence should depend on a maintainer repeating a checklist.

Amended 2026-09-01 ([#55](https://github.com/thiagobrez/react-native-reorderable/issues/55)): the screenshot-feedback proof — Apple Vision OCR of mid-hold screenshots plus destination pixel-diff thresholds — is removed from the publication gate, producer sampling included. The four-engine accessibility-tree parity comparison and Detox end-state assertions satisfy the user-observable intent; a deterministic React Native Testing Library assertion that the drag-preview and destination-highlight render paths activate during a simulated drag covers the broken-render-wiring regression class, and Detox's per-test videos remain the human-reviewable visual record. Pixel-level compositing regressions are accepted as dogfooding-caught risk rather than machine-verified, because the OCR/pixel apparatus proved fragile out of proportion to the regressions it could catch.

Amended 2026-09-02 ([#57](https://github.com/thiagobrez/react-native-reorderable/issues/57)): every check now has exactly one owning workflow and one lifecycle point, replacing the duplicated per-PR surface (lint/typecheck ran 2–4×, Reassure and geometry twice, and the exact package candidate blocked every pull request at a 45-minute median and 31% pass rate). Pull requests run only fast deterministic checks under a **≤10-minute wall-clock budget**; the fast workflows drop their push-to-`main` triggers because the ruleset's strict up-to-date requirement means a merged pull request's checks already describe the `main` state. The exact package candidate runs one uniform job set on every push to `main`, so every `main` SHA is release-eligible; publication chains off the candidate's success for the exact release SHA via `workflow_run`, replacing the race-prone `gh run list` poll. A nightly schedule re-runs the candidate as a drift canary and adds a non-gating peer-version canary that installs against the latest React Native, Reanimated, and Gesture Handler releases.

| Check | Owning workflow (job) | Lifecycle point |
| --- | --- | --- |
| Lint + typecheck | `ci.yml` (`lint`) | PR |
| Unit + release-policy tests, incl. the RNTL render-path backstop | `ci.yml` (`test`) | PR |
| Example Android / iOS builds (working CocoaPods cache) | `ci.yml` (`build-android`, `build-ios`) | PR |
| Documentation build (no separate typecheck) | `docs.yml` (`build`) | PR |
| Changeset requirement | `changeset-requirement.yml` | PR |
| Reassure render gates + geometry benchmarks | `performance.yml` | PR |
| Exact tarball pack + artifact verification (once) + sha256 (once) | `exact-package-candidate.yml` | Push to `main` + nightly |
| Clean package and native consumers | `exact-package-candidate.yml` | Push to `main` + nightly |
| Minimum Android / iOS runtime floors | `exact-package-candidate.yml` | Push to `main` + nightly |
| Four-engine device contract + parity | `exact-package-candidate.yml` | Push to `main` + nightly |
| Peer-version canary (non-gating) | `exact-package-candidate.yml` (nightly-only job) | Nightly |
| Publication | `release.yml`, triggered by `workflow_run` on candidate success | Release |

Pruned as redundant or unused: the candidate's duplicate `quality` and `render-regressions` jobs, `ci.yml`'s `build-library` job (a strict subset of `test`), all `merge_group` triggers (no merge queue is configured), coverage collection (collected twice, enforced nowhere), the duplicate package-artifact verification and sha256 re-checks, and the manual named-scenario device-verification scripts. Physical-device performance validation is removed from the lifecycle entirely: Reassure render gates plus geometry benchmarks on hosted CI are the accepted performance proof, and device-specific performance regressions join the dogfooding-caught risk class ([#45](https://github.com/thiagobrez/react-native-reorderable/issues/45) closed accordingly). The required checks on `main` become `lint`, `test`, `build-android`, `build-ios`, the documentation `build`, `geometry`, `render-regressions`, and the changeset requirement; `build-library` and the tarball-approval check leave the PR gate.
